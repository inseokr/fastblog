Design: Photo Finale in CreatingRecapView

Animation timeline for the 5-second blog creation screen

Animation Timeline (5s total)
Rings + nodes + % counter
Real photos fall + dissolve + flash
0s 1s 2s 3s ← photos start 4s 5s → blog
0 – 3s (unchanged)
  • Rotating dashed ring
  • Filling progress ring
  • Nodes assemble (photo / text / sparkle)
  • Step labels + % counter
Fades to 0 opacity over 0.4s at 3s mark
3 – 5s (new finale)
  • Up to 12 real photos fall from top
  • Staggered 100ms apart
  • Slight rotations, scattered positions
  • Dissolve at 4.3s (blur + scale down)
  • White flash at 4.6s
Blog reveals at 5s via existing goToLanding()
What changes
CreatingRecapView.swift
  • New photoIdentifiers: [String] param
  • PHAsset thumbnail loading on appear
  • Falling photo state vars + animation
  • Phase 1 UI fades at 3s mark
  • Falling photos phase in remaining 2s
CreateBlogFlowView.swift
  • Extract up to 12 isSelected photo identifiers from trip
  • Pass to CreatingRecapView
No new files needed
Photo loading

PHAsset thumbnails are loaded via PHImageManager at view appear (same approach as MockPhotoView). Small delivery size (~200pt) to avoid memory spikes. If a photo hasn't loaded by the time it needs to fall, it shows a gradient tile fallback — so the animation is never blocked.
